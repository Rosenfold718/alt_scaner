# 🚀 Альткоин-сканер пампов

Приложение в реальном времени отслеживает все USDT-пары альткоинов на Binance (те же цены, что TradingView
показывает по символам `BINANCE:XXXUSDT`) и ловит пампы — рост цены на заданный процент за заданное окно времени.

## Что делает

- **Сканирует ~500 спотовых USDT-пар** Binance со статусом TRADING (стейблкоины, плечевые токены и BTC исключены —
  BTC не альткоин; чтобы включить его, удалите `'BTCUSDT'` из `EXCLUDED_SYMBOLS` в
  `mini-services/pump-service/index.ts`).
- **Детектирует памп**: сравнивает текущую цену монеты с ценой N минут назад (по умолчанию окно 5 минут,
  нижний порог 3%, верхняя граница 10%). Рост ≥ нижнего порога → сигнал «ПАМП», рост выше верхней границы →
  «СИЛЬНЫЙ ПАМП».
- **Без повторов**: по монете приходит один сигнал на эпизод роста — пока её рост держится выше нижнего
  порога, новых сигналов не будет, даже если монета продолжает дорожать. Монета снова доступна для
  детекции, только когда рост откатится ниже порога и продержится там 30 секунд (плюс антиспам-кулдаун
  3 минуты от дребезга у самого порога).
- **Сохраняет историю сигналов в базу SQLite** (Prisma, файл `db/custom.db`): каждый сигнал пишется в таблицу
  `PumpSignal`, при старте сервиса последние 200 загружаются обратно в журнал. История переживает перезапуски
  и не теряется при обрывах соединения. Если база недоступна, сканер продолжает работать в памяти.
- **Формирует сообщение о скачке**: тикер, цена, процент роста, готовая строка вида
  `🚀 SOLUSDT +4.21% за 5 мин | 146.20 → 152.35 USDT` — её можно скопировать кнопкой в интерфейсе и переслать куда угодно.
- **Живой дашборд**: журнал пампов за сессию (новые сверху, с вспышкой при появлении), показатели сессии
  (сигналы, уникальные монеты, лучший памп, пары в скане), статус потоков, клик по тикеру открывает график
  монеты на TradingView.

## Архитектура

| Компонент | Порт | Назначение |
| --- | --- | --- |
| `src/app/page.tsx` (Next.js) | 3000 | Дашборд: журнал сигналов, пороги, статусы |
| `mini-services/pump-service/index.ts` | 3003 | Ядро: WebSocket Binance (`!miniTicker@arr`), скользящее окно цен, детектор пампов, socket.io-сервер |

Связь дашборда с ядром — socket.io (события `init`, `pump`, `status`, `config`; клиентские `config:update`).
В песочнице запросы идут через шлюз Caddy (`/?XTransformPort=3003`), локально — напрямую на порт 3003.

На старте ядро подключается к потоку Binance сразу, а скользящее окно «засеивается» историей 1-секундных свечей
(REST `klines`, interval `1s`) мягкими батчами с паузами — сканер ловит пампы без 5-минутного прогрева. Если REST
временно недоступен (лимит Binance), детекция просто прогревается живым потоком. Список пар обновляется каждые
10 минут — новые листинги подхватываются автоматически.

## Запуск локально (вне песочницы)

Требуется [Bun](https://bun.sh) (или Node.js 20+ для `next dev`).

```bash
# 0. Из корня проекта: env, зависимости, клиент Prisma и база SQLite (создаст db/custom.db)
cp .env.example .env
bun install
bun run db:generate
bun run db:push
cd mini-services/pump-service && bun install && cd ../..   # зависимости ядра-сканера

# 1. Дашборд (порт 3000) — он сам поднимет ядро-сканер на порту 3003
bun run dev
```

Открыть `http://localhost:3000`. Дашборд сам определит локальный запуск и подключится к `localhost:3003`.

> Ядро-сканер стартует автоматически вместе с сервером Next.js (`src/instrumentation.ts`): если порт 3003
> уже занят работающим сервисом, автостарт пропускается, а упавший сервис поднимется при следующем
> перезапуске сервера. Запустить вручную тоже можно: `cd mini-services/pump-service && bun run dev`.

## Настройка порогов

Поля «Нижний порог, %» и «Верхняя граница, %» меняются на лету прямо в интерфейсе (кнопка «Применить»).
Диапазон по умолчанию: 3–10%. Всё, что выше верхней границы, показывается с меткой «СИЛЬНЫЙ ПАМП» —
верхнюю границу можно поднять (например, до 100), чтобы ловить только экстремальные движения.

## Структура проекта

```
mini-services/pump-service/   # ядро-сканер (Binance WS → окно → детектор → socket.io + SQLite)
src/app/page.tsx              # дашборд (единственная пользовательская страница)
src/app/layout.tsx            # метаданные
prisma/schema.prisma          # модель PumpSignal — сохранённые сигналы
db/custom.db                  # база SQLite с историей сигналов (создаётся db:push, в git не входит)
scripts/test-client.mjs       # тестовый socket-клиент: проверка потока событий
scripts/test-history.mjs      # тестовый клиент: проверка загрузки истории из базы
scripts/test-dedup.mjs        # симуляция анти-повтора: 1 сигнал на эпизод роста
```

> Сам файл базы (`db/custom.db`) и `.env` в git не входят — они создаются локально при первом запуске
> (см. шаг 0 выше), чтобы история сигналов оставалась только у вас.

> ⚠️ Данные публичные, ключи API не нужны. Приложение носит информационный характер и не является
> инвестиционной рекомендацией.
